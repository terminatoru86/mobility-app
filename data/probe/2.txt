        <h1 id="authentication" tabindex="-1"><a class="header-anchor" href="#authentication">Authentication</a></h1>
<p>The Bikeep API supports three authentication methods, each designed for different integration scenarios. Choose the one that fits your use case.</p>
<h2 id="choosing-an-auth-method" tabindex="-1"><a class="header-anchor" href="#choosing-an-auth-method">Choosing an Auth Method</a></h2>
<table>
<thead>
<tr>
<th>Method</th>
<th>Best For</th>
<th>Session Tracking</th>
<th>Payment Support</th>
<th>Complexity</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>S2S OAuth2</strong></td>
<td>Backend integrations, IoT management</td>
<td>No</td>
<td>No</td>
<td>Low</td>
</tr>
<tr>
<td><strong>External Users</strong></td>
<td>Mobile apps, user-facing products</td>
<td>Yes</td>
<td>Yes</td>
<td>Medium</td>
</tr>
<tr>
<td><strong>Public Access</strong></td>
<td>Map displays, availability widgets</td>
<td>N/A</td>
<td>N/A</td>
<td>None</td>
</tr>
</tbody>
</table>
<h3 id="decision-guide" tabindex="-1"><a class="header-anchor" href="#decision-guide">Decision guide</a></h3>
<ul>
<li><strong>“I want to control hardware from my backend”</strong> → S2S OAuth2</li>
<li><strong>“I want to build a mobile app where users park and pay”</strong> → External Users</li>
<li><strong>“I just want to show availability on a map”</strong> → Public Access</li>
</ul>
<hr>
<h2 id="s2s-oauth2-service-to-service" tabindex="-1"><a class="header-anchor" href="#s2s-oauth2-service-to-service">S2S OAuth2 (Service-to-Service)</a></h2>
<p>The simplest method. Your backend authenticates directly with Bikeep using client credentials.</p>
<h3 id="how-it-works" tabindex="-1"><a class="header-anchor" href="#how-it-works">How it works</a></h3>
<pre class="mermaid">
sequenceDiagram
    participant Server as Your Server
    participant Auth as Bikeep Auth
    participant API as Bikeep API

    Server->>Auth: POST /oauth2/token<br/>(client_id + client_secret)
    Auth-->>Server: access_token (1h TTL)
    Server->>API: GET /location/v1/...<br/>Authorization: Bearer token
    API-->>Server: JSON response
</pre>
<h3 id="get-a-token" tabindex="-1"><a class="header-anchor" href="#get-a-token">Get a token</a></h3>
<pre class="language-bash"><code class="language-bash"><span class="token function">curl</span> <span class="token parameter variable">-X</span> POST https://auth.bikeep.com/oauth2/token <span class="token punctuation">\</span>
  <span class="token parameter variable">-H</span> <span class="token string">"Content-Type: application/x-www-form-urlencoded"</span> <span class="token punctuation">\</span>
  <span class="token parameter variable">-d</span> <span class="token string">"grant_type=client_credentials"</span> <span class="token punctuation">\</span>
  <span class="token parameter variable">-d</span> <span class="token string">"client_id=YOUR_CLIENT_ID"</span> <span class="token punctuation">\</span>
  <span class="token parameter variable">-d</span> <span class="token string">"client_secret=YOUR_CLIENT_SECRET"</span></code></pre>
<p><strong>Alternative:</strong> Pass credentials as Basic Auth:</p>
<pre class="language-bash"><code class="language-bash"><span class="token function">curl</span> <span class="token parameter variable">-X</span> POST https://auth.bikeep.com/oauth2/token <span class="token punctuation">\</span>
  <span class="token parameter variable">-H</span> <span class="token string">"Authorization: Basic BASE64(client_id:client_secret)"</span> <span class="token punctuation">\</span>
  <span class="token parameter variable">-H</span> <span class="token string">"Content-Type: application/x-www-form-urlencoded"</span> <span class="token punctuation">\</span>
  <span class="token parameter variable">-d</span> <span class="token string">"grant_type=client_credentials"</span></code></pre>
<p><strong>Response:</strong></p>
<pre class="language-json"><code class="language-json"><span class="token punctuation">{</span>
  <span class="token property">"access_token"</span><span class="token operator">:</span> <span class="token string">"eyJhbGciOiJSUzI1NiIs..."</span><span class="token punctuation">,</span>
  <span class="token property">"token_type"</span><span class="token operator">:</span> <span class="token string">"Bearer"</span><span class="token punctuation">,</span>
  <span class="token property">"expires_in"</span><span class="token operator">:</span> <span class="token number">3600</span>
<span class="token punctuation">}</span></code></pre>
<h3 id="token-usage" tabindex="-1"><a class="header-anchor" href="#token-usage">Token usage</a></h3>
<p>Include the token in every API request:</p>
<pre><code>Authorization: Bearer eyJhbGciOiJSUzI1NiIs...
</code></pre>
<p>Tokens expire after <strong>1 hour</strong>. Request a new token before expiry — there is no refresh token in the S2S flow.</p>
<h3 id="limitations" tabindex="-1"><a class="header-anchor" href="#limitations">Limitations</a></h3>
<p>S2S OAuth2 does not create user identities, so:</p>
<ul>
<li><strong>No session tracking</strong> — device sessions will not be associated with users</li>
<li><strong>No payment processing</strong> — usage fees cannot be charged</li>
<li><strong>No user statistics</strong> — usage history is not available</li>
</ul>
<p>If you need these features, use External Users.</p>
<hr>
<h2 id="external-users-3rd-party-apps" tabindex="-1"><a class="header-anchor" href="#external-users-3rd-party-apps">External Users (3rd Party Apps)</a></h2>
<p>For mobile apps and user-facing products that need full session tracking, payments, and statistics. This method involves a handshake between your backend and Bikeep to verify user identities.</p>
<h3 id="how-it-works-1" tabindex="-1"><a class="header-anchor" href="#how-it-works-1">How it works</a></h3>
<pre class="mermaid">
sequenceDiagram
    participant App as Your App
    participant Server as Your Server
    participant API as Bikeep API

    Note over App,API: Sign-up
    App->>Server: sign up
    Server->>API: POST /sign-up<br/>(user_id, operator_id)
    API->>Server: POST to your sign-up endpoint<br/>{user_id, bikeep_user_id}
    Server-->>API: 200 OK
    API-->>Server: 204 No Content
    Server-->>App: store bikeep_user_id

    Note over App,API: Sign-in
    App->>Server: sign in
    Server->>API: POST /sign-in<br/>(bikeep_user_id, operator_id,<br/>challenge_token)
    API->>Server: POST to your sign-in endpoint<br/>{user_id, challenge_token}
    Server-->>API: {bikeep_user_id}
    Note right of API: Bikeep verifies match
    API-->>Server: access_token + refresh_token
    Server-->>App: ready

    App->>API: API calls with Bearer token
</pre>
<h3 id="prerequisites" tabindex="-1"><a class="header-anchor" href="#prerequisites">Prerequisites</a></h3>
<p>You must implement two verification endpoints on your server that Bikeep will call:</p>
<p><strong>1. Sign-up verification endpoint</strong></p>
<p>Bikeep POSTs to this endpoint when a user first registers:</p>
<pre class="language-json"><code class="language-json"><span class="token comment">// POST to your endpoint</span>
<span class="token punctuation">{</span>
  <span class="token property">"user_id"</span><span class="token operator">:</span> <span class="token string">"your-internal-user-id"</span><span class="token punctuation">,</span>
  <span class="token property">"bikeep_user_id"</span><span class="token operator">:</span> <span class="token string">"bikeep-uuid-for-this-user"</span>
<span class="token punctuation">}</span></code></pre>
<p>Your endpoint <strong>must store the <code>user_id</code> → <code>bikeep_user_id</code> mapping</strong> — you will need the <code>bikeep_user_id</code> for all subsequent sign-in and API calls.</p>
<p>Respond with any <code>2xx</code> status to confirm.</p>
<blockquote>
<p><strong>Status codes:</strong> Bikeep treats <code>&lt; 400</code> as success, <code>4xx</code> as rejection (<code>ERRORS.OPERATOR_REJECTION</code>), and <code>5xx</code> as an error (<code>ERRORS.OPERATOR_ERROR</code>).</p>
</blockquote>
<p><strong>2. Sign-in verification endpoint</strong></p>
<p>Bikeep POSTs to this endpoint on every sign-in attempt. The payload includes the <code>challenge_token</code> — the same value your app originally sent to <code>/sign-in</code>:</p>
<pre class="language-json"><code class="language-json"><span class="token comment">// POST to your endpoint</span>
<span class="token punctuation">{</span>
  <span class="token property">"user_id"</span><span class="token operator">:</span> <span class="token string">"your-internal-user-id"</span><span class="token punctuation">,</span>
  <span class="token property">"challenge_token"</span><span class="token operator">:</span> <span class="token string">"the-nonce-your-app-sent-to-sign-in"</span>
<span class="token punctuation">}</span></code></pre>
<p>Your endpoint must <strong>validate the <code>challenge_token</code></strong> — confirm it matches a recently generated nonce for this user. This proves the sign-in was initiated by your app (see <a href="#how-the-challenge_token-works">How the challenge_token works</a> below).</p>
<p>If valid, respond with the <code>bikeep_user_id</code>:</p>
<pre class="language-json"><code class="language-json"><span class="token punctuation">{</span>
  <span class="token property">"bikeep_user_id"</span><span class="token operator">:</span> <span class="token string">"bikeep-uuid-for-this-user"</span>
<span class="token punctuation">}</span></code></pre>
<p>Bikeep verifies that this <code>bikeep_user_id</code> matches the one sent in the original <code>/sign-in</code> request. If it does not match, the sign-in is rejected.</p>
<p>If the challenge token is invalid, respond with <code>4xx</code> to reject the sign-in.</p>
<blockquote>
<p><strong>Status codes:</strong> Bikeep treats <code>&lt; 400</code> as success (proceeds to match <code>bikeep_user_id</code>), <code>4xx</code> as rejection (sign-in denied), and <code>5xx</code> as an error.</p>
</blockquote>
<blockquote>
<p><strong>Timeout:</strong> Both verification endpoints must respond within <strong>5 seconds</strong>. If your endpoint does not respond in time, the request fails with <code>504</code> and error code <code>ERRORS.SERVICE_TIMED_OUT</code>.</p>
</blockquote>
<h3 id="how-the-challenge_token-works" tabindex="-1"><a class="header-anchor" href="#how-the-challenge_token-works">How the challenge_token works</a></h3>
<p>The <code>challenge_token</code> is a short-lived nonce that proves a sign-in request was initiated by your app — not by a third party who happens to know a <code>bikeep_user_id</code>.</p>
<p><strong>The round-trip:</strong></p>
<ol>
<li>Your app generates a unique, short-lived token (nonce) for this sign-in attempt</li>
<li>Your app sends it to Bikeep via <code>POST /sign-in</code> along with the <code>bikeep_user_id</code></li>
<li>Bikeep forwards it to your sign-in verification endpoint — Bikeep never inspects the content, it only requires the field to be non-empty</li>
<li>Your server validates the token, proving the request originated from your app</li>
</ol>
<pre class="mermaid">
sequenceDiagram
    participant App as Your App
    participant Server as Your Server
    participant Bikeep

    App->>Server: (1) generate nonce
    Server->>Bikeep: (2) POST /sign-in<br/>{bikeep_user_id, challenge_token}
    Bikeep->>Server: (3) POST callback<br/>{user_id, challenge_token}
    Server->>Server: (4) validate nonce
    Server-->>Bikeep: {bikeep_user_id}
    Bikeep-->>Server: access_token
    Server-->>App: ready
</pre>
<blockquote>
<p><strong>Security:</strong> Without a valid <code>challenge_token</code>, anyone who knows a <code>bikeep_user_id</code> could sign in as that user. Always generate a cryptographically random nonce, store it server-side with a short TTL (e.g., 60 seconds), and reject any token your server did not recently issue.</p>
</blockquote>
<h3 id="sign-up-a-user" tabindex="-1"><a class="header-anchor" href="#sign-up-a-user">Sign up a user</a></h3>
<pre class="language-bash"><code class="language-bash"><span class="token function">curl</span> <span class="token parameter variable">-X</span> POST https://services.bikeep.com/external-users-auth/v1/sign-up <span class="token punctuation">\</span>
  <span class="token parameter variable">-H</span> <span class="token string">"Content-Type: application/json"</span> <span class="token punctuation">\</span>
  <span class="token parameter variable">-d</span> <span class="token string">'{
    "user_id": "your-internal-user-id",
    "operator_id": "your-operator-uuid"
  }'</span></code></pre>
<blockquote>
<p><strong>Partial failure recovery:</strong> If sign-up succeeds on Bikeep’s side but your verification endpoint fails (returns 4xx/5xx or times out), the API returns an error — but the user already exists in Bikeep’s system. To recover:</p>
<ol>
<li><strong>Retry the sign-up.</strong> Bikeep handles duplicates automatically — your verification endpoint will be called again with the <code>user_id</code> and <code>bikeep_user_id</code>, giving you another chance to store the mapping.</li>
<li><strong>If you already have the <code>bikeep_user_id</code></strong>, skip straight to sign-in. The sign-in verification callback includes the <code>user_id</code>, so you can re-establish the mapping at that point.</li>
</ol>
</blockquote>
<h3 id="sign-in-a-user" tabindex="-1"><a class="header-anchor" href="#sign-in-a-user">Sign in a user</a></h3>
<pre class="language-bash"><code class="language-bash"><span class="token function">curl</span> <span class="token parameter variable">-X</span> POST https://services.bikeep.com/external-users-auth/v1/sign-in <span class="token punctuation">\</span>
  <span class="token parameter variable">-H</span> <span class="token string">"Content-Type: application/json"</span> <span class="token punctuation">\</span>
  <span class="token parameter variable">-d</span> <span class="token string">'{
    "bikeep_user_id": "bikeep-uuid-for-this-user",
    "operator_id": "your-operator-uuid",
    "challenge_token": "your-app-generated-nonce"
  }'</span></code></pre>
<table>
<thead>
<tr>
<th>Field</th>
<th>Description</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>bikeep_user_id</code></td>
<td>The Bikeep UUID you received during sign-up (stored in your <code>user_id</code> → <code>bikeep_user_id</code> mapping)</td>
</tr>
<tr>
<td><code>operator_id</code></td>
<td>Your operator UUID (provided by Bikeep)</td>
</tr>
<tr>
<td><code>challenge_token</code></td>
<td>A short-lived nonce your app generated for this sign-in attempt — Bikeep forwards it to your verification endpoint for validation</td>
</tr>
</tbody>
</table>
<p><strong>Response:</strong></p>
<pre class="language-json"><code class="language-json"><span class="token punctuation">{</span>
  <span class="token property">"access_token"</span><span class="token operator">:</span> <span class="token string">"eyJhbGciOiJSUzI1NiIs..."</span><span class="token punctuation">,</span>
  <span class="token property">"refresh_token"</span><span class="token operator">:</span> <span class="token string">"eyJhbGciOiJSUzI1NiIs..."</span>
<span class="token punctuation">}</span></code></pre>
<h3 id="refresh-a-token" tabindex="-1"><a class="header-anchor" href="#refresh-a-token">Refresh a token</a></h3>
<pre class="language-bash"><code class="language-bash"><span class="token function">curl</span> <span class="token parameter variable">-X</span> POST https://services.bikeep.com/external-users-auth/v1/refresh <span class="token punctuation">\</span>
  <span class="token parameter variable">-H</span> <span class="token string">"Content-Type: application/json"</span> <span class="token punctuation">\</span>
  <span class="token parameter variable">-d</span> <span class="token string">'{
    "bikeep_user_id": "bikeep-uuid-for-this-user",
    "refresh_token": "eyJhbGciOiJSUzI1NiIs..."
  }'</span></code></pre>
<blockquote>
<p><code>operator_id</code> is also accepted but optional (for debugging only). Only <code>bikeep_user_id</code> and <code>refresh_token</code> are required.</p>
</blockquote>
<p><strong>Response:</strong></p>
<pre class="language-json"><code class="language-json"><span class="token punctuation">{</span>
  <span class="token property">"access_token"</span><span class="token operator">:</span> <span class="token string">"eyJhbGciOiJSUzI1NiIs..."</span>
<span class="token punctuation">}</span></code></pre>
<p>Access tokens expire after <strong>1 hour</strong>. Use the refresh token to get a new access token without requiring the user to sign in again. The refresh endpoint returns only a new <code>access_token</code> — the original <code>refresh_token</code> remains valid and should be reused for subsequent refreshes.</p>
<h3 id="error-reference" tabindex="-1"><a class="header-anchor" href="#error-reference">Error reference</a></h3>
<p>All error responses follow this format:</p>
<pre class="language-json"><code class="language-json"><span class="token punctuation">{</span>
  <span class="token property">"error_code"</span><span class="token operator">:</span> <span class="token string">"ERRORS.EXAMPLE_ERROR"</span><span class="token punctuation">,</span>
  <span class="token property">"error_message"</span><span class="token operator">:</span> <span class="token string">"human-readable description"</span><span class="token punctuation">,</span>
  <span class="token property">"status_code"</span><span class="token operator">:</span> <span class="token number">400</span>
<span class="token punctuation">}</span></code></pre>

<h2 id="public-access" tabindex="-1"><a class="header-anchor" href="#public-access">Public Access</a></h2>
<p>No authentication required. Only one endpoint is publicly accessible:</p>
<pre class="language-bash"><code class="language-bash"><span class="token function">curl</span> https://services.bikeep.com/location/v1/public-areas/<span class="token punctuation">{</span>public_area_id<span class="token punctuation">}</span>/locations</code></pre>
<p>This returns location data in <strong>GeoJSON format</strong> including availability counts. Use it for public-facing maps and availability displays.</p>
<p>See the <a href="/use-cases/availability-display/">Availability Display</a> guide for integration examples.</p>
<blockquote>
<p><strong>Note:</strong> The <code>public_area_id</code> is provided by Bikeep and defines a geographic region (e.g., a city or campus) whose locations are publicly visible.</p>
</blockquote>
