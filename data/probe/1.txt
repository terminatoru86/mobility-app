        <h1 id="availability-display" tabindex="-1"><a class="header-anchor" href="#availability-display">Availability Display</a></h1>
<p>Show real-time bike parking availability on maps, dashboards, or mobile apps using the bike parking availability API. This guide is for <strong>any consumer of Bikeep availability data</strong> — including municipalities publishing open data portals, transit agencies integrating bike parking into journey planners, campus IT teams embedding availability in campus apps, and third-party mobility platforms. The Bikeep public endpoint returns location data with availability counts in GeoJSON format — <strong>no authentication required</strong>.</p>
<blockquote>
<p><strong>Important:</strong> The API provides <strong>data only</strong>, not a pre-built UI. You use the data to build your own display — a map marker, a dashboard widget, a mobile app screen, etc.</p>
</blockquote>
<hr>
<h2 id="the-public-endpoint" tabindex="-1"><a class="header-anchor" href="#the-public-endpoint">The Public Endpoint</a></h2>
<pre class="language-bash"><code class="language-bash"><span class="token function">curl</span> https://services.bikeep.com/location/v1/public-areas/<span class="token punctuation">{</span>public_area_id<span class="token punctuation">}</span>/locations</code></pre>
<p>No <code>Authorization</code> header needed. The <code>public_area_id</code> defines a geographic region (e.g., a city, campus, or venue). Public areas are typically created by Bikeep during onboarding, but partner-level integrators can also create and manage their own public areas via the API.</p>
<p><strong>Response (GeoJSON — <code>application/geo+json</code>):</strong></p>
<pre class="language-json"><code class="language-json"><span class="token punctuation">{</span>

<h2 id="polling-for-updates" tabindex="-1"><a class="header-anchor" href="#polling-for-updates">Polling for Updates</a></h2>
<p>The public endpoint returns the current state at the time of the request. To keep your display up-to-date, poll the endpoint periodically.</p>
<p>Bike parking availability changes slowly — a station might see a handful of events per hour. Polling every <strong>5–10 minutes</strong> is a good fit for most use cases.</p>
<p><strong>Recommended intervals:</strong></p>
<ul>
<li><strong>Public display / signage:</strong> Every 5–10 minutes</li>
<li><strong>Mobile app:</strong> Every 5–10 minutes, or on screen focus</li>
<li><strong>Dashboard:</strong> Every 5 minutes</li>
</ul>

<h2 id="authenticated-alternative" tabindex="-1"><a class="header-anchor" href="#authenticated-alternative">Authenticated Alternative</a></h2>
<p>If you need more detailed device-level data (individual device states, hardware health, booking status), use the authenticated endpoint instead:</p>
<pre class="language-bash"><code class="language-bash"><span class="token function">curl</span> https://services.bikeep.com/location/v1/locations <span class="token punctuation">\</span>
  <span class="token parameter variable">-H</span> <span class="token string">"Authorization: Bearer {token}"</span></code></pre>
<p>This returns richer location data with device-level detail — individual device states, hardware health, and diagnostic information. See <a href="/authentication/">Authentication</a> for setup.</p>
